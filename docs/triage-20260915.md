The runlist path still falls back as described, so a decode half remains after merge.
**Action:** **merge #2376**, then close out the remaining runlist/decode fallback and the "`FAIL G` should name the missing shape" diagnostic-improvement note.

### #2307 — `npu` · `bug` — non-fused p1/p2 split int4 path is silently unhealthy
**Severity:** silent corruption. The non-fused (p1/p2 split) int4 path emits `rms=4.6e8` (rebuilt artifact) or writes nothing (`rms=0.0000`, `corr=-nan` on the committed artifact) — with no error surfaced. Filed from #2282's closing notes so it isn't lost in a merged-PR body; 7 comments.
**Action:** **fix now** — repair the non-fused path or make it refuse loudly; ensure the fused path (which is correct) remains the default.

### #2213 — `npu` · `bug` — decode not bit-reproducible with a fixed seed
**Severity:** correctness/nondeterminism in the compute path. With identical sampler inputs, concurrent instances diverge at token 3. Root-caused to a **host-side aliasing race**: K and V copies share one pinned staging buffer that is refilled for V without waiting for the K copy (`npu_engine_fused.hip:1259-1272`); the window was measured at a few µs. The non-fused i8-MoE path is 17/17 identical, localising the race to the fused HIP KV path. Diagnostic reproducer in PR #2344; 8 comments.
**Action:** **fix now** — serialize/split the KV staging upload; the race is diagnosed, the fix is a bounded change.

### #2377 — `npu` · `bug` — 6 concurrent npu_engine instances exhaust NPU host memory
**Severity:** crash under concurrency, with a misleading cause. N ≤ 5 is clean across 17 starts; N = 6 aborts ~25% of the time on `mmap … ENOMEM`, then dies with a bogus "heap corruption from free(): invalid size" SIGABRT. A discrete cliff, not gradual degradation; 1 comment.
**Action:** **fix now** — find the per-instance host-memory oversubscription and fix the abort attribution (it masks the real ENOMEM).

### #2418 — `engine` · `bug` — GLM-MoE-DSA gate fails when it actually runs (and never runs in CI)
**Severity:** correctness-assurance hole. The comparator gate reports green while never executing: the e2e phases are gated on `/tmp/onebit-*` fixture dirs nothing creates. The *engine* bug (indexer RoPE convention) is already fixed via #2421 (merged `92378e13e`, comparator now passes). What remains is the CI gap. 4 comments.
**Action:** **fix now** — generate the GLM-MoE-DSA fixtures in CI so the gate actually runs; a green-but-never-run gate is worse than a red one.

### #2145 — `hrx` · `bug` — llama_state-imported context fails HRX0-device decode at token 2
**Severity:** blocks the #1942 D2 hybrid fast path. Root-caused (and corrected once): the shipped b66 HRX bundle **over-claims `FLASH_ATTN_EXT` above KV 2048**, so a 2,940-token imported context can't decode; a second defect (per-request reset drops imported KV) was also found. Fix branch `fix/2145-hrx-ctx-limit` exists but **no PR opened**. 16 comments.
**Action:** **fix now** — open a PR from the fix branch (guard + second defect) and gate it behind the bundle ceiling.
