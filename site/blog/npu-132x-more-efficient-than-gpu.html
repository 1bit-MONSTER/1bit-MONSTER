NPU Architecture Deep Dive

bong-water-water-bong · July 6, 2026 · 5 min read

Retracted: “the NPU is 132× more efficient than the GPU”

tl;dr: This post's central claim — that the XDNA 2 NPU delivers 145 tok/s/W vs the GPU's 1.1 tok/s/W, a 132× efficiency advantage — is retracted. Every number it depended on is either unsourced in this repository or contradicted by it, and the per-component watt breakdown was presented as measurement with no measurement behind it. The post is kept here for history, rewritten to say that.

What was wrong

The 132× ratio reduces arithmetically to (291 / 2) / (22 / 20) — i.e. it is entirely dependent on the NPU's 291 tok/s fused-layer figure and on the ~2 W / ~20 W power figures. All three are problems:

  • 291 tok/s (NPU fused) — benchmarks/latest.json _unverified.npu_fused_raw_tok_s: “NO SOURCE anywhere in the repo. Contradicted by docs/npu/AGENTS.md (4.8 tok/s).” The README itself marks the NPU-fused path “broken” and “not currently reproducible”.
  • 55.7 TFLOPS — _unverified.tflops_55_7: “NO SOURCE. Measured ternary prefill peak is 35.57 TFlops.”
  • The watt breakdown (“Memory controller ~4W, shader array ~10W, cache ~4W, driver ~2W, compute ~2W” for the GPU; “compute tiles ~1.2W, SRAM ~0.5W, interface ~0.3W” for the NPU) — there is no rapl/powertop/HSA power read or any power-measurement methodology anywhere in the repo. These numbers were fabricated for the post.

Remove 291 tok/s — which the repo has — and the 132× collapses. The architectural arguments below (spatial dataflow, SRAM locality, single xclbin dispatch) are plausibly directionally true and are the real reason an NPU can be efficient for this workload, but they were dressed up here with specific tok/s/W and watt numbers that this project cannot substantiate.

What would be needed to make the claim

A real comparison requires: (1) a currently-reproducible NPU tok/s figure from a verified-correct run (the fused path does not currently produce validated generation), and (2) sustained wall-power measurement during that run and an equivalent GPU run, with methodology recorded in benchmarks/. Neither exists. Until they do, no tok/s/W or “N× more efficient” claim should appear on this site as fact.

The original (architectural) argument, kept for context

Spatial dataflow, not SIMD

The XDNA 2 NPU is a spatial dataflow architecture — compute tiles are configured with a fixed dataflow graph at load time and data streams through the AIE tiles, rather than spending per-instruction fetch/decode/scheduling power as a GPU SIMD unit does.

SRAM locality and single dispatch

Each AIE tile has local SRAM, and the fused layer does all per-layer operations in one xclbin call, avoiding driver round-trips between operations. These are reasonable reasons an NPU can win on efficiency — but “by 132×” is not something this repo can currently back.
